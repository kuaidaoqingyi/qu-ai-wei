# 文件与基线

仅在写回文件、保存广播站基线或记录套话候选时读取。正文保真与修改范围仍以 `../SKILL.md` 为准。

## 原稿和写回

改文件前保留原件或不覆盖的版本副本；不替用户发布、上传或同步。写回后回读实际文件，核对保护区和本轮改动。试改只在隔离副本中进行，不改用户定稿。

## 广播站基线

广播站目录由用户或当前工作区配置确定，操作前解析真实路径，旧入口可能是兼容链接。使用同一真实目录下的脚本和源稿，避免根目录不匹配；不要从公开技能包猜测用户的本机目录。

完成正文写回后，立刻在广播站真实目录执行：

```bash
node .qu-ai-wei-baselines/baseline-tool.mjs save "源文件绝对路径" --skill qu-ai-wei
```

不覆盖旧基线。回读脚本返回的新基线及元数据，确认其内容与写回稿一致，成功后才报告“已保存 AI 改稿基线”。失败则明确说明“正文已写回，基线未保存”，不要宣称全部完成。

只审阅、给建议、聊天内改写和隔离验证时，不保存正式稿基线。需要验证保存能力时，把脚本复制到隔离目录的 `.qu-ai-wei-baselines/` 下，对同目录中的试改副本执行，不调用正式目录的保存流程。

## 套话候选持续收集

已有模板及晋升流程见 `ai-cliche-library.md`。只有用户明确指出的新模板、库中未覆盖的明显可复用骨架，或在独立文本中重复出现的同类模式才记录；没有新模式不写日志。

- 仅留抽象骨架，人物、机构、产品、日期、数字和具体事实替换成 `____`。
- 每个文本最多记录两条，不保存原文长句、私人信息、引用和受保护文本。
- 候选累计三次后，仅在用户要求迭代技能时人工复核，再晋升；收集候选不触发技能修改或 GitHub 推送。已明确授权的技能同步另按维护流程执行，不包含候选日志或真实稿件。

从当前活动技能目录调用：

```bash
node scripts/cliche-log.mjs add \
  --pattern "抽象后的套话骨架" \
  --family "病灶族" \
  --action "默认处理动作" \
  --source "文本类型" \
  --file "/path/to/broadcast/.qu-ai-wei-baselines/ai-cliche-candidates.json"
```

非广播站文本沿用已有的候选日志位置。不要因加载本参考而创建新日志，也不把单篇作者口头禅升级成通用禁令。
