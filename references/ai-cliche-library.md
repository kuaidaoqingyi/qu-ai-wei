# AI 空话套话活库

这个文件只用于识别和删除模板，禁止从中挑句式生成正文。命中某个词不等于必须删除；要结合上下文判断它是否遮住事实、重复意思或制造假深刻。

表格里的“写具体事实、动作、结果”都指原文或用户材料中已经存在的内容。材料没有细节时，直接删除空壳或保留克制判断，禁止用常识补齐。

## 收录标准

确认模板满足至少一项：

- 用户明确指出它有明显 AI 味。
- 在三个独立文本中出现同类骨架。
- 它能套进多数题材，删除后信息不受影响。
- 它承担的主要功能是凑完整、拔高、假共情或拖延进入事实。

单篇里的个人口头禅、行业术语、引用、标题、法律和政策原文不进入活库。

## 已确认模板

### 空背景

| 识别骨架 | 常见问题 | 默认动作 |
| --- | --- | --- |
| `随着____不断发展` | 先铺时代舞台，迟迟没有事件 | 删除，直接写人、事、数字或问题 |
| `在____时代背景下` | 背景可以替换成任何题材 | 删除 |
| `当前正处于____关键阶段` | 重要性没有事实支撑 | 写清发生了什么 |
| `____正以前所未有的速度____` | 用速度感代替证据 | 补时间、变化幅度和对象 |
| `近年来，____逐渐成为关注焦点` | 无具体时间和关注主体 | 写明谁在何时关注什么 |

### 空重要性

| 识别骨架 | 常见问题 | 默认动作 |
| --- | --- | --- |
| `值得注意的是____` | 用提示词强行提权 | 直接写事实 |
| `不难发现____` | 把判断包装成共识 | 给依据或删掉提示词 |
| `毋庸置疑____` | 回避论证 | 补证据和条件 |
| `显而易见____` | 把有争议判断写成常识 | 写清判断来源 |
| `这一现象值得我们深入思考` | 没有提出具体问题 | 改成一个可回答的问题 |

### 假洞察和固定对照

| 识别骨架 | 常见问题 | 默认动作 |
| --- | --- | --- |
| `不是____，而是____` | 普通转折被包装成顿悟 | 删除否定铺垫，直接写结论 |
| `不只是____，更是____` | 强行升级意义 | 留下有证据的一层 |
| `不仅仅是____，更是____` | 事实被抬成宏大价值 | 改成具体结果 |
| `与其说____，不如说____` | 为对照牺牲准确性 | 写成两句判断和原因 |
| `表面上____，背后其实____` | 套用揭密结构 | 直接说明机制 |
| `真正的____在于____` | 用“真正”制造权威 | 写清条件和证据 |
| `关键不在于____，而在于____` | 延迟说重点 | 直接说重点 |

### 凑完整的列举

| 识别骨架 | 常见问题 | 默认动作 |
| --- | --- | --- |
| `从____到____` | 两端不在同一尺度 | 改成真实范围 |
| `无论是____，还是____` | 多项只是凑覆盖面 | 保留影响最大的对象 |
| `首先____，其次____，最后____` | 顺序没有真实逻辑 | 改成时间、因果或动作 |
| `一方面____，另一方面____` | 两边没有取舍 | 写清优先级 |
| `既要____，又要____` | 对称填充 | 写清代价和选择 |
| `____、____、____共同构成` | 三个抽象词互相可换 | 留下真正展开的一项 |

### 无源权威

| 识别骨架 | 常见问题 | 默认动作 |
| --- | --- | --- |
| `研究表明____` | 没有研究名称和来源 | 补来源；核不到就删 |
| `数据显示____` | 没有数据口径 | 补时间、样本和来源 |
| `有专家指出____` | 专家身份模糊 | 写明姓名和机构，或删除 |
| `业内普遍认为____` | “业内”没有边界 | 写明具体主体 |
| `大量案例证明____` | 没有案例 | 补案例或降成判断 |

### 抽象动作和通稿腔

| 识别骨架 | 常见问题 | 默认动作 |
| --- | --- | --- |
| `为____注入新动能` | 没有动作和结果 | 写清谁做了什么 |
| `为____提供有力支撑` | 支撑内容不可检查 | 写具体能力和结果 |
| `持续赋能____` | 主语、动作和受益方模糊 | 改成真实使用关系 |
| `助力____高质量发展` | 通稿结论 | 补指标或删除 |
| `构建____新格局` | 结果不可验证 | 写具体变化 |
| `打造____生态闭环` | 多个抽象词叠加 | 拆成参与者、流程和收益 |
| `实现效率与体验双提升` | 两项都没有展开 | 选一项给证据 |

### 假分析尾巴

| 识别骨架 | 常见问题 | 默认动作 |
| --- | --- | --- |
| `这体现了____` | 事实后面挂空意义 | 删除尾巴 |
| `这彰显了____` | 宣传评价 | 换成事实 |
| `这标志着____` | 单点事件被写成时代节点 | 给时间线和依据 |
| `这背后反映出____` | 自动上升到宏观问题 | 解释具体机制 |
| `为未来____奠定了坚实基础` | 预测没有可检验内容 | 写当前结果 |
| `这或许正是____的最佳注脚` | 文学化总结可以套任何主题 | 删除或回到具体画面 |

### 伪人话

| 识别骨架 | 常见问题 | 默认动作 |
| --- | --- | --- |
| `说白了，____` | 后文仍然抽象 | 真正换成普通动作 |
| `简单来说，____` | 只是重复上句 | 删除重复 |
| `你可能会问____` | 伪造读者问题 | 只有真实疑问才保留 |
| `问题来了____` | 路标过密 | 直接进入问题 |
| `换句话说____` | 同义复述 | 后句没有新信息就删 |
| `从某种意义上说____` | 模糊判断责任 | 写清判断范围 |

### 万能收尾

| 识别骨架 | 常见问题 | 默认动作 |
| --- | --- | --- |
| `尽管仍面临挑战，未来依然值得期待` | 固定挑战展望公式 | 写具体困难或直接停住 |
| `未来可期` | 与正文无关的积极收尾 | 删除 |
| `让我们拭目以待` | 主持腔 | 写真实未知或下一次验证 |
| `我们有理由相信____` | 理由通常没有展开 | 给依据或删除 |
| `这需要每一个人的共同努力` | 责任主体消失 | 写清谁负责什么 |
| `机遇与挑战并存` | 没有取舍和条件 | 写出一个真实机会或风险 |

### 信息复读

| 识别骨架 | 常见问题 | 默认动作 |
| --- | --- | --- |
| 连续使用“换句话说、也就是说、从这个角度看” | 多次解释同一结论 | 只留最清楚的一次 |
| 每段结尾都写“这说明、这意味着、这反映” | 段段上价值 | 保留有新机制的一处 |
| 结论后继续写两三段意义 | 结尾拖堂 | 停在最后一个有效事实、动作或画面 |
| 后半段反复出现“更重要、更深层、真正值得关注” | 程度升级代替信息 | 删除程度词，检查有没有新内容 |

## 候选收集

新模式先进入本地日志：

```bash
node scripts/cliche-log.mjs add \
  --pattern "抽象骨架" \
  --family "病灶族" \
  --action "默认动作" \
  --source "文本类型"
```

记录时：

1. 把姓名、机构、产品、日期和数字替换为 `____`。
2. 只保留能复用的短骨架，不复制整段原文。
3. 同一骨架再次出现时累计次数。
4. 每个文本最多新增两条。
5. 引用、法律政策原文、专有术语和用户私人表达不记录。

## 晋升规则

用户要求迭代技能时：

1. 列出累计 3 次以上的候选。
2. 检查是否已经被现有病灶覆盖。
3. 合并同义骨架。
4. 人工确认它确实会造成空话、重复或假深刻。
5. 加入本文件，并在需要时更新 `ai-bingzao.md`。
6. 运行静态检查和行为样本，再同步本地与 GitHub。
