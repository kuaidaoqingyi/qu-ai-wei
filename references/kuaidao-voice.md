# 快刀青衣文风参考

用户明确要求“按我的文风”“快刀青衣文风”“广播站个人文风”“像我早期文章”时使用。先完成 `ai-bingzao.md` 诊断，再结合 `broadcast-style.md` 校准。

本文件来自虎嗅专栏语料提炼。早期文章提供写作骨架，近年文章补证据、验收和责任。它只负责文风，不能充当事实来源，也不能把样本文中的事件、数字和经历搬进新稿。

文风校准只做选材、重排、压缩和表达。材料没有的人物、任务、机制、因果和经历全部留空。原文信息不足时，短而准确优先。

## 一句话标准

把抽象问题拖进一个具体人、具体场景和真实代价里，让概念落地，再给出一个有来源、愿意负责的判断。

## 使用顺序

1. 先锁定一条主线。
2. 从早期骨架里选入口、场景和角色关系。
3. 用近期理性层补事件、来源、任务、信任和责任。
4. 检查作者材料来源。
5. 选择合适结尾。

一篇文章只需要一条中心判断。新闻、数字、案例和比喻都服务这条主线。

中心判断可以把原文已有含义说清楚，不能凭常识新增行业机制、战略意图和因果关系。

## 早期骨架

### 私人动机

原文已经给出尴尬、愤怒、好奇、被误解、失败或现实教育时，可以把它放到前面。这类动机让判断带着作者风险。

原文没有私人动机时，保留当前视角，不补“我忍不住说两句”之类的人设。

### 具体现场

优先使用面试、带孩子、看球、用产品、带团队、朋友对话、失败项目和离谱新闻等真实现场。

有效现场包含人、动作、麻烦和结果。只有地点和气氛，仍然属于空背景。

### 高概念落到低场景

AI、模型、战略、组织、效率、创新等大词，要放进普通人能感知的任务中检验：

- 谁多做了工作。
- 哪一步真的省掉了。
- 谁要学习新工具。
- 谁承担失败。
- 结果由谁验收。

场景负责解释概念，不能只负责制造反差。

### 角色关系

把产品、技术和组织问题翻译成角色之间的关系：

- 谁制定规则。
- 谁执行。
- 谁等待。
- 谁受益。
- 谁占便宜。
- 谁背结果。

关系清楚后，抽象判断自然会落地。

### 承认不体面

原文已有狼狈、私心、外行感、失败经验和不确定时，优先保留。这些内容让作者站在事情里面。

自黑只负责降低姿态，不能削弱事实和判断。

### 幽默落回机制

段子、类比和吐槽都要推进认识。读者笑完以后，文章还要说清产品、技术、组织或人性机制。

## 近期理性层

### 事件锚点

开头或前几段尽快交代可核查事件：时间、机构、人物、产品版本、政策、论文、报告或测试对象。

时代背景不能替代事件。

### 作者是验收者

优先保护原文中的研究动作：

- 读了哪些材料。
- 测了哪些功能。
- 问了哪些人。
- 看了哪个过程。
- 对了哪些数据和口径。

这些动作说明判断从哪里来。原文没有时不要补写。

### 真实任务

能力、效率、智能、生产力和工作流必须落到可执行、可检查、可复盘的任务。

写清楚它替谁省了哪一步，又把哪些检查和责任留给了人。

原文没有具体任务时，保留抽象判断或提示作者补材料，不自行编一个常见场景。

### 信任分级

复杂话题按可信程度处理：

- 已经发生、来源明确、可以复核的事实，可以相信。
- 主场数据、内部口径和单方叙事，保留方向信号，同时写清条件。
- 情景推演、宣传标题、夸张倍数和局部经验，暂不当作事实。

判断要说明可信到哪一层。

### 责任链

至少回答一个问题：

- 谁公布数据。
- 谁从这个说法中受益。
- 谁能复核。
- 谁验收结果。
- 谁承担后果。
- 谁最后签字。

### 慢变量

技术速度要经过用户习惯、组织信任、教育制度、法律责任和真实场景校准。

写清机器能加快哪一步，人和组织仍然卡在哪一步。

## 主线和信息密度

- 开头先立“为什么值得聊”，再选择事实。
- 产品名单、新闻清单和研究引用都要挂在主线上。
- 与主线关系弱的风险支线、理论引用和案例可以整段删除。
- 官方口径、作者判断和推测保持原有证据等级。
- 新增具体人物、动作、任务、结果和机制时，逐项回到原文找依据；找不到就删除。
- 每段增加事实、机制、经历、判断、动作或必要转场。
- 后半段感慨重复时，保留最具体的一处。
- 作者复杂经历要保住条件、结果和矛盾，不压成简单成功或失败。

## 句子、段落和问句

- 段落跟着思路单元走。短段适合包袱和判断，长段可以靠路标带听众走完。
- 避免机械切成一句一段。
- 保留自然口语，删除密集语气词。
- 问句用于真实反驳、困惑和悬念，每个问题后面要有事实、判断或动作。
- 感叹号保持克制。
- 禁用否定 A、再转向 B 的固定对照句。
- 避免把“真正、关键、本质、说白了”当成反复出现的发令枪。

## 结尾

根据文章选择：

- 产品和组织稿可以停在一个短判断。
- 工具和学习稿可以落到一个可执行动作。
- 故事和体验稿可以回到开头画面。
- 研究和教育稿可以停在真实悬念或下一次验证。

结尾不强求金句，不重复全文，也不统一变成自测题。

## 改写动作表

| 原文状态 | 改写动作 |
| --- | --- |
| 开头抽象 | 换成已有私人动机、具体现场、事件或读者麻烦 |
| 只有新闻清单 | 先锁主线，再筛选能解释主线的事实 |
| 概念太大 | 放进真实任务和角色关系里检验 |
| 只有信息整理 | 恢复原文已有的作者反应和研究过程 |
| 作者经历被压平 | 保住条件、代价、矛盾和结果 |
| 分条模板化 | 每条补角色、动作、代价和判断，删除可互换项 |
| AI 话题太玄 | 落到任务、验收、复核、签字和谁受益 |
| 单方叙事 | 做信任分级，交代来源和成立条件 |
| 技术进步写得过快 | 补用户、组织、制度和责任等慢变量 |
| 后半段松散 | 删除弱支线和重复感慨，回到主线 |
| 结尾用力 | 从判断、动作、场景、悬念中换一种自然收法 |

## 禁止项

- 不编作者经历、搜索过程和第一反应。
- 不模仿粗口、性别化段子和冒犯性表达。
- 不把专业内容改成鸡汤或段子。
- 不为人味故意制造错别字、网感词和口头禅。
- 不用固定对照句制造顿悟。
- 不把样本文中的虎嗅、罗辑思维、得到、产品名和人物经历搬到无关稿件。

## 最后回读

1. 开头是否有具体人、事件、任务或麻烦？
2. 主线能否用一句话说清？
3. 作者材料能否追溯到原文？
4. 相关关系有没有被升级成因果、战略或能力瓶颈？
5. 大词是否只在材料支持时落到真实任务和角色关系？
6. 每段是否有信息增量？
7. 事实、判断、推演和宣传叙事是否分开？
8. 技术判断是否经过慢变量校准？
9. 后半段是否删掉弱支线和重复感慨？
10. 结尾是否选择了合适收法？
11. 锋利感是否来自事实和判断？
