# 快刀青衣文风参考

当用户说“按我的文风”“快刀青衣文风”“广播站文风”“像我早期文章”“说人话但要像我”时使用。先完成 `ai-bingzao.md` 的去味诊断，再结合 `broadcast-style.md` 做补味，最后用本文件校准作者声音。

本文件来自虎嗅专栏语料提炼，优先参考 2013-2016 年早期文章。它是风格规则，不是事实来源；不要把样本文中的事件、数据或经历搬进用户新稿。

## 一句话标准

快刀青衣的“说人话”，不是把句子改口语，而是把抽象问题拖进一个具体人、一个具体场景、一段真实代价里，让概念在地上走两步，然后给出一个愿意负责的判断。

## 使用顺序

1. **先用早期骨架。** 找私人动机、具体现场、高反差类比、角色关系和段子后的判断。
2. **再用近期理性层。** 补事件锚点、来源、时间线、真实任务、信任分级、谁受益、谁验收、谁负责。
3. **最后做边界检查。** 保留锋利和现场感，不复制粗口、性别化段子、过时冒犯性表达。

## 早期文风核心

早期最强的不是“无节操”，而是“用高反差场景把高概念拉下神坛，再从荒诞细节里抠出一个产品、技术或组织判断”。

保留三件事：

- 敢把严肃问题放进不严肃场景。
- 敢承认作者自己的狼狈、私心和不体面。
- 段子最后必须翻译成一个可执行判断。

不要保留三件事：

- 为了像早期文章而故意粗俗。
- 用冒犯性外壳替代判断。
- 让吐槽压过事实。

## 标题和入口

优先用“高概念 + 低场景”的反差入口。

可用方向：

- 技术概念下沉：AI、模型、工具、产品能力，要落到一个普通人会遇到的动作。
- 管理概念下沉：组织、协作、效率、战略，要落到角色、关系、代价。
- 私人身份开路：产品经理、奶爸、外行、用户、被现实教育过的人。
- 反差场景上桌：生活琐事、职场尴尬、家庭场景、江湖故事、失败经历。

避免：

- “随着 AI 时代到来”这类时代背景开场。
- 只用惊悚标题，正文不能兑现反差。
- 为了复古而使用今天明显不合适的性别化、低俗化表达。

## 五种开头动作

### 1. 私人动机

先写“我为什么非得说这件事”。这个动机可以是尴尬、愤怒、好奇、被误解、被现实教育，不一定要宏大。

可用结构：

```text
我本来不想写____，但____这件事让我有点憋不住。
因为它表面上是在说____，背后其实是____。
```

### 2. 生活现场

不先定义概念，先写一个动作场景：面试、带孩子、看球、用产品、被朋友吐槽、看到一个离谱新闻。

判断标准：读者开头 30 秒内能不能看见人、动作和麻烦。

### 3. 荒诞反差

找一个和主题不在同一领域、但结构相似的场景。反差不是装饰，而是认知杠杆。

可用结构：

```text
这件事看起来像____，但更像____。
前者讲的是____，后者暴露的是____。
```

### 4. 先自黑

作者可以先降姿态：我不是专家，我只是从一个具体角色里看见了问题。自黑是为了让强判断不端着，不是为了自贬。

### 5. 连续问句

早期文章问句很密。迁移时可以用问句模拟读者脑子里的反驳，但每个问句后面必须接例子、判断或动作，不要连续空问。

## 推进方式

### 先段子，后概念

不要一上来解释“大词”。先给一个错得很具体、荒诞得很真实的场景，再告诉读者它背后是什么概念。

可用结构：

```text
这个例子听起来像段子，但它真正说明的是：____。
```

### 分条但不模板

可以分条，但每条都要像一个小故事：

- 有角色。
- 有动作。
- 有代价。
- 有一句判断。

不要只列抽象名词。三点之间如果能互换，就是模板味。

### 把概念变成角色关系

早期文章常把产品、技术、组织问题翻译成人和人的关系。改稿时要问：

- 这里谁像老板，谁像员工？
- 谁在追求谁，谁在躲谁？
- 谁多干了活，谁少承担了责任？
- 谁看起来体面，其实在占便宜？
- AI 在这里是外包、搭子、监工、学生，还是审稿人？

### 每个概念都要被降格

遇到大词先放到低成本、低体面、真实场景里试一下。它在这个场景里还能成立，才是真概念；站不住，就是包装词。

可用结构：

```text
大家都在讲____，听起来特别高级。
但如果把它放进____这个场景里，你会发现它其实只是在解决____。
```

## 句子和段落

- 段落要短。一个段落只做一件事：设场、打岔、判断、举例、转向。
- 保留自然路标：其实、但是、那么、所以、当然、问题是。
- 可以有情绪，但情绪只负责开门，判断负责收口。
- 不把三个判断塞进一段，也不把每段都写成总结句。
- 早期的感叹号密度很高；今天迁移时要少用，保留力度，不保留用力感。

## 判断方向

优先补这些判断：

- 这个概念放到真实场景里还站得住吗？
- 谁因为这个机制多干了活？
- 谁看起来在创新，其实只是在转移成本？
- 谁拿到了好处，谁承担了后果？
- 用户真正被减负了，还是被迫学习了更多东西？
- 数据、图表、案例有没有口径陷阱？
- 一个产品功能是在解决问题，还是在频刷存在感？

## 近期理性补层

近年风格不是替代早期风格，而是在早期的现场感和反差入口上，补一层证据、验收和责任。（语料覆盖状态见仓库 README，随抓取进度更新，不写死在本文件里。）

近期风格的一句话标准：先承认真信号，再拆夸张叙事，最后落到普通人如何验收、如何使用、如何避免被概念带跑。

处理 AI、产品、组织、监管、教育、职场话题时，在早期骨架之外补七件事。

### 1. 事件先钉住，再开判断

不要从时代背景开始，先交代一个可核查的事件：哪天、谁、发布了什么、发生了什么、测试了什么、哪份报告或论文说了什么。

可用动作：

- 开头用具体日期、机构、人物、产品版本、政策、论文或测试对象。
- 紧接着补作者第一反应：我为什么觉得这里有意思、不对劲或值得追。
- 不用“近年来、随着、在 AI 时代”替代具体事件。

### 2. 作者是验收者，不只是吐槽者

近年作者更常以“读完、试过、听完、面试过、聊过、看过过程的人”进入。作者在场不是为了加情绪，而是说明判断从哪里来。

优先补：

- 我读了什么。
- 我测了什么。
- 我问了谁。
- 我看了哪个过程。
- 我把哪些数据或口径对了一遍。

### 3. 把大词翻译成真实任务

遇到“能力、效率、智能、重塑、趋势、生产力、工作流”这类大词，先问它落在哪个具体任务上。

好的任务要能被执行、检查和复盘，例如：

- 把长文档变成可编辑表格。
- 逐条核查引用是否真实存在。
- 把工厂质检从抽检变成全检。
- 在真实职场场景里处理一条复杂任务链。

不要只写“提升效率”“改变行业”。要写它具体替谁省了什么步骤，又把什么验收责任留给了人。

### 4. 建立信任分级

近年强判断不是简单站队，而是分层相信。

可用分级：

- **可以相信**：已经发生、可核查、有明确来源的事实。
- **谨慎相信**：来自主场数据、内部数据、单方叙事，但方向上有信号。
- **暂时不要当事实**：情景推演、宣传标题、夸张倍数、把局部经验包装成全局规律。

复杂话题里，用“可信到哪一层”替代“真/假、牛/不牛”。

### 5. 追问谁受益、谁验证、谁负责

AI 味常常没有责任主体。近年文风会把判断钉回责任链。

至少补一个问题：

- 谁公布数据？
- 这个数据在什么条件下成立？
- 这个说法对谁有利？
- 谁有动机把它讲大？
- 谁能复核？
- 谁有能力验收结果？
- 谁承担后果？
- 谁最后签字负责？

### 6. 用慢变量抵消技术狂飙

技术可以快，但人的习惯、组织信任、教育制度、法律责任、用户场景很慢。近年写法会把“机器速度”和“人类速度”的裂缝讲出来。

可用判断：

- 代码能很快写出来，不等于用户会很快接受。
- 模型能生成方案，不等于组织有能力验收。
- 工具能替人干活，不等于责任能自动转移。
- 产品能上线，不等于真实场景已经打磨出来。

### 7. 结尾给判断标准，而不是只给金句

早期结尾常靠锋利判断收住。近年结尾更像给读者一个下次可复用的判断动作。

可用方向：

- 凡是看到____，先降一档信任。
- 凡是遇到____，先问谁验收。
- 凡是有人宣称____，先看它成立的条件。
- 凡是工具看起来很强，先问它把责任留给了谁。

## 改写动作表

| 原文问题 | 改写动作 |
| --- | --- |
| 开头抽象 | 换成私人动机、具体现场或高反差场景。 |
| 概念太端着 | 放到生活、职场、产品使用或组织协作里降格验证。 |
| 只有结论 | 补角色、动作、代价和责任主体。 |
| 只有信息整理 | 补作者反应：我为什么觉得这里不对劲。 |
| 分条模板化 | 每条改成“小故事 + 判断”，删掉可互换抽象词。 |
| AI 话题太玄 | 落到真实任务、验收、复现、审核、签字、谁受益。 |
| 只有单方叙事 | 做信任分级：哪些可信、哪些谨慎信、哪些暂不当事实。 |
| 技术进步写得太快 | 补慢变量：用户习惯、组织信任、监管责任、真实场景。 |
| 结尾鸡汤 | 改成“以后再看到类似事，先问什么”。 |

## 可用句式

这些是方向，不是模板。每篇最多挑 2 条，不要集中连用；“不是...而是”类句式计入全文硬上限（2 处）。

- “这件事听起来很高级，但放到____里，其实就是____。”
- “我真正想问的是：____到底替谁省了事，又把麻烦转给了谁？”
- “如果只看表面，这是____；但如果看角色关系，它更像____。”
- “这个例子有点像段子，但它说明了一个很正经的问题：____。”
- “以后再看到____，别先问____，先问____。”
- “这件事里有三层东西要分开看：事实是____，判断是____，它希望你接受的叙事是____。”
- “____可以被 AI 加速，但____不行。前者是工具问题，后者是人的问题、组织问题、责任问题。”
- “这件事对普通人真正有用的地方，不是知道____又变强了，而是知道____该由谁验证、谁负责。”

## 禁止项

- 不编作者亲身经历。
- 不模仿粗口和冒犯性段子。
- 不把专业内容改成鸡汤或段子。
- 不为了“人味”故意加错别字、口头禅和网感词。
- 不用“不是而是”堆出假深刻；只有真实误解需要拆时才用。
- 不把样本文中的虎嗅、罗辑思维、得到、Anthropic 等事实搬到无关文本里。

## 最后回读

改完后问八个问题：

1. 开头有没有私人动机、具体现场或高反差入口？
2. 抽象概念有没有被放到低场景里验证？
3. 段子有没有落回产品、技术、组织或人性判断？
4. 文本有没有回答“谁受益、谁负责、谁验收”里的至少一个？
5. 早期味道是来自判断方式，还是只来自粗糙外壳？
6. 近年理性层有没有区分事实、判断、推演和叙事？
7. 技术进步有没有被真实任务和慢变量校准？
8. 结尾是不是留下一个下次可复用的问题，而不是情绪升华？
