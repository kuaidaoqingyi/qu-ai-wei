# 广播站文风补味

在文本是广播站稿件、口播稿、公众号稿，或用户要求“按我的文风”时使用。先完成去味层，再用本文件补回作者声音。

目标不是把稿子改得更正式，而是让它像一个人站在听众面前，把复杂事情讲明白：有对象感，有路标，有判断，有能带走的一句话。

默认读者是“广播站/得到 AI 学习圈用户”：对 AI 感兴趣，但不是来听术语汇报；愿意学习，但注意力有限；最关心的是“这件事和我有什么关系，我该怎么判断，我能不能做点什么”。

## 文风骨架

1. **具体事件开场**：从一个新闻、人物、产品、事故、反常点进入；如果新案例需要上下文，可以先用一两句旧案例、现实痛点或作者观察接住听众，但不从“时代背景”进入。
2. **作者第一反应**：保留“我看到这里也愣了一下”“说实话我第一反应是...”这种真实入口。
3. **作者研究过程**：如果原文里有真实的搜索、测试、截图、抓数据、对比、访谈或使用过程，优先保留成判断来源，不只留下结论。
4. **先故事，后机制**：先让读者知道发生了什么，再拆目标、流程、激励、约束和反作用。
5. **产品经理式拆解**：多问“它改变了谁的行为”“谁被迫多干了活”“谁最后负责”。
6. **认知落差**：先松动旧看法，再给新判断；不要只堆资料。
7. **责任锚点**：AI 相关话题尤其要落到“谁判断、谁签字、谁负责、谁愿意押信誉”。
8. **可带走动作**：结尾优先留一个读者下次能复述、能迁移、能自测的问题或判断。

## 补味动作表

| 目标 | 要问 | 动作 |
| --- | --- | --- |
| 补对象感 | 我到底在跟谁说？他卡在哪？ | 开头 30 秒内交代读者为什么要听。 |
| 补入口 | 这事最反常的地方是什么？ | 用具体冲突、常见误解、作者反应开场。 |
| 补作者在场 | 这个判断从哪里来？ | 保留读过、试过、抓过、对比过、面试过等真实过程；没有就不要编。 |
| 补路标 | 读者会在哪里跟丢？ | 在论文、数据、商业模式、技术机制前加一句短路标。 |
| 补人话 | 术语能不能翻译成场景？ | 英文词、人名和概念先转成能听懂的中文；必要时保留原词和精确数字。 |
| 补机制 | 这件事怎么运转？ | 拆目标、参与者、激励、限制、后果。 |
| 补事实取舍 | 哪些事实推动主线？ | 保留能解释主线的历史线、对照和关键数字，删掉名单式堆叠。 |
| 补关键比喻 | 听众是否真的跟上了？ | 一个核心类比可以多走一步成操作场景；不要堆多个浅比喻。 |
| 补判断 | 读者听完多了什么判断？ | 把“知道一个信息”改成“以后遇到 X，先问 Y”。 |
| 补责任 | 谁为结果负责？ | 明确谁审核、谁签字、谁承担后果。 |
| 补收束 | 结尾能不能复述或自测？ | 留一句判断或一个自测问题，避免“未来可期”和情绪升华。 |

## 常用句式

这些是路标，不是模板。只在读者可能跟丢时使用。

- “这句话听起来有点绕，我翻译一下。”
- “关键问题来了：它到底改变了谁的行为？”
- “注意，这里不是说 X，而是说 Y。”
- “讲到这里，我们先把线头捋一下。”
- “这件事真正麻烦的地方在于...”
- “如果只记一句话，就是...”
- “以后你再看到类似事情，可以先问一个问题：...”
- “我不是只看了结论，而是把____也翻出来看了一遍。”
- “你也可以拿____自测一下：____？”

## 开头改法

优先三种入口：

1. **场景入口**：如果你是某个具体人，正在遇到什么麻烦？
2. **误解入口**：很多人以为这事是 A，其实真正的问题是 B。
3. **个人反应入口**：我看到这个案例、数据或论文时，第一反应是什么？
4. **旧案/痛点入口**：读者需要上下文时，先用最近讲过的案例、现实痛点或作者观察接住，但只用一两句，马上回到新闻。

尽量避免：

- “近年来，随着...不断发展”
- “某某报告指出...”
- “在当今时代，...已经成为重要趋势”
- “本文将从三个方面展开分析”

## 结尾改法

结尾不要只做总结或情绪升华，要留下可复述判断。面向学习圈用户时，优先给一个能立刻拿自己的岗位、项目或流程对照的自测问题。

可用结构：

```text
所以以后再看到____，我们不要先问____，而要先问____。
```

```text
这件事给普通人的提醒是：____。不是因为____，而是因为____。
```

```text
AI 时代真正稀缺的，不是____，而是____。
```

```text
你也可以拿自己的____自测一下：这件事到底改变了哪一步，谁来验收？
```

注意：全文“不是…而是”类句式硬上限 2 处（含结尾模板和补味新加的）。正文已经用过，结尾就换别的收法，不要再套“AI 时代真正稀缺的，不是...而是...”这类模板。

## 保留作者味

优先保留：

- “说实话”“其实”“你看”“问题来了”这类自然口语。
- 作者的第一反应、犹豫、吐槽和自嘲。
- 作者怎么查材料、怎么试产品、怎么抓数据、怎么对比、怎么形成判断的过程。
- 对产品、流程、激励、副作用的拆解。
- 具体例子和生活类比。
- 把英文术语、产品名、人名翻成顺口中文的口播处理，但保住必要原词和关键数字。
- 能签字、能负责、能押信誉的强判断。

不要把这些自然口语改平。改稿不是把稿子变正式，而是让读者更容易跟上作者的思路。

## 反过度补味

不要为了“像作者”硬加：

- 不存在的亲身经历。
- 过密的“说实话、其实、你看”。
- 太多吐槽，压过事实。
- 明明不确定却写成强判断。
- 把复杂问题改成段子。
- 为了顺口删掉关键事实、数字或限定条件。
- 把所有数字都改成约数；只有不影响判断时才口播化。
- 把单篇里的具体案例、照片、书名、产品名沉淀成固定套路。

## 验收三问

1. 读者开头 30 秒内知道为什么要听吗？
2. 读者听完能复述一个判断吗？
3. 有没有一句话需要重读才能懂？

只要第三问答案是“有”，继续拆句、补路标或换成人话。不要用空泛总结遮住理解障碍。
