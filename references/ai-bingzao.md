# AI 病灶识别表

先判断病灶族，再决定动作。词语命中只算线索；真正要看的是信息、责任、对象和推进有没有被遮住。需要核对大量固定套话时，再读 `ai-cliche-library.md`。

## 最高优先级

| 病灶 | 典型信号 | 核心问题 | 建议动作 |
| --- | --- | --- | --- |
| 没有对象 | 开头只讲时代、行业、趋势 | 没有人、没有事、没有读者问题 | 换成具体人、事件、场景或麻烦 |
| 没有真主语 | “得到了提升”“实现了优化” | 谁做、谁判断、谁负责都不见了 | 换成真人、团队、机构、系统或流程 |
| 无源权威 | 研究、数据、专家没有出处 | 借模糊权威撑结论 | 公开写作删铺垫；文档标“缺来源” |
| 假具体 | “某个用户”“一个典型案例”没有细节 | 例子只有外壳 | 用原文细节补全；没有就删例子壳 |
| 常识补写 | 抽象的效率、体验、趋势被改成备课、反馈、岗位职责等具体场景 | 具体细节看似合理，原文没有依据 | 删除新增细节；允许改后稿保持简短 |
| 借来的作者感受 | 原文没有第一人称，改稿突然出现“我试了”“我很震惊” | 为了人味编经历和情绪 | 删除虚构内容；只保留原文可追溯的作者材料 |
| 作者退出现场 | 原文有真实测试、采访、使用或判断过程，改稿只留下结论 | 作者声音被资料腔压平 | 恢复已有过程和判断来源 |
| 推断升级 | 招聘变化被直接写成战略转向，相关关系被写成因果或瓶颈 | 改稿替作者下了更强结论 | 恢复原证据等级和限定词；缺依据的机制删掉 |
| 信息复读 | 相邻段落换词重复同一结论 | 字数增加，认识没有前进 | 合并或删除后一段 |
| 占位符或对话残留 | “此处插入案例”“当然可以，以下是” | 暴露提示词和界面残留 | 一票否决，删除后全文重读 |
| 假引用 | 文献、DOI、链接或归属对不上 | 伪造证据 | 核查；核不到就删或标待核实 |

## 结构与推进

| 病灶 | 典型信号 | 核心问题 | 建议动作 |
| --- | --- | --- | --- |
| 宏大时代开场 | 技术浪潮、时代背景、重要趋势先铺一段 | 读者迟迟看不到事情 | 删除，直接进入事件或问题 |
| 二元对比假戏剧 | 先否定 A，再把 B 写成顿悟 | 普通转折被包装成洞察 | 默认禁用；只说 B，或拆成两句因果 |
| 否定式列举 | 连续排除多个答案后才说重点 | 绕路制造悬念 | 直接给重点 |
| 价值拔高骨架 | 普通事实被抬成宏大意义 | 姿态大于信息 | 降到动作、结果或责任 |
| 三件套排比 | 三个抽象词并列，每项都不展开 | 用完整感代替分析 | 留下真正有信息的一两项 |
| 对称填充 | 成对结构反复出现，取舍不明 | 为整齐牺牲判断 | 写清优先级和代价 |
| 破折号穷举 | 破折号后跟一串抽象名词 | 用标点制造揭晓感 | 拆成正常句，删无信息项 |
| 机械递进 | 首先、其次、最后只负责排版 | 顺序没有真实逻辑 | 改成时间、因果、取舍或动作顺序 |
| 戏剧化碎句 | 多个极短句只为制造力量感 | 节奏表演压过事实 | 合成正常句 |
| 反问式铺垫 | 问题没有真实悬念，答案立刻自报 | 延迟进入事实 | 直接给判断和依据 |
| 信息增量不足 | 一段只解释上一段已经说过的话 | 文章原地踏步 | 合并、删除或补新事实和机制 |
| 感慨膨胀 | 后半段连续写“意义、启示、值得思考” | 情绪重复，信息密度骤降 | 只留最有用的一次收束 |
| 结尾拖堂 | 结论已成立，后面又总结两三段 | 文章停不下来 | 在最后一个有效事实、动作或画面处停住 |
| 挑战展望公式 | 先承认困难，再统一展望光明未来 | 任何题目都能套 | 写具体困难、应对或真实未知 |
| 和稀泥收尾 | 各有利弊、因人而异、取决于需求 | 回避取舍 | 写明条件和选择 |

## 信息增量判定

内部给每段标一个主要功能：事实、机制、经历、判断、动作、转场。

- 相邻两段功能相同、结论相同，后一段通常可以删。
- 新段落只增加“更重要、更深刻、更值得思考”等程度词，视为零增量。
- 一个例子没有改变判断，也没有补机制，视为装饰性例子。
- 结论出现后，后文只换说法解释意义，视为结尾拖堂。
- 删除一段后事实链和论证链都不受影响，优先删除。

## 快速判定

- 删除第一段后正文照常成立，多半是空开场。
- 删除否定铺垫后更清楚，多半是假对照。
- 三个并列项可以互换，多半是模板排比。
- 破折号后是一串抽象词，多半是穷举汇总。
- 句子里找不到人、机构、系统或流程，多半缺真主语。
- 后半段连续三段没有新事实、机制和动作，多半在重复感慨。
- 第一人称内容无法追溯到原文，多半是借来的作者感受。
- 原文只显示相关变化，改稿却写成因果、战略或能力瓶颈，多半是推断升级。
- 新增的具体动作和对象只能靠常识解释，无法在原文定位，多半是常识补写。

## 防止误杀

- 技术文档中的系统主语、字段名、被动句可以保留。
- 正式汇报需要结构，不要强行改成聊天。
- 广播站口语路标可以保留，前提是帮助听众跟上。
- 承载事实的抽象句先保事实，再改外壳。
- 原文没有动作和场景时，不用常识替它补具体案例。
- 引用、标题、法律和政策原文即使命中套话，也保持原样。
