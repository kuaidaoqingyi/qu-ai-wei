# 去 AI 味的边界回归

这些测试检查改稿有没有越界，不检测作者身份。`cases.json` 中的 19 个输入全部为自拟测试材料，不是用户的真实经历。`review-checklist.json` 是审阅标准，不是唯一正确措辞。新增边界覆盖：双指标未展开、顺序无关的独立功能、结论重复但证据不同的段落。

## 运行一次实际改稿

1. 让独立的执行者读取技能主文件及相关参考，只提供 `cases.json` 的 request 和 input。不提供审阅清单、历史结果或预期答案。
2. 每条按独立请求处理。保存为 JSON 对象，键为案例 id。改写题的值只放成稿，无需改动时放原文，不混入“不需要改”、解释或外围代码围栏；诊断题的值放建议。这个输出格式要求一并提供给执行者，不提供具体答案。文件题返回完整文件内容；需要写文件时仅在隔离副本操作，不触碰原稿。
3. 在技能目录执行 `node scripts/check-preservation.mjs /absolute/path/outputs.json`，检查覆盖完整性、指定原样片段、段落数和顺序。
4. 再按 `review-checklist.json` 人工逐条核对语义。不能因为字符串仍在就认定归因、条件或因果正确。
5. 记录执行模型、日期、各项输出和实际问题。失败先修最小规则，再用新实例复测，不能只对旧答案调词。

本轮技能升级可按 skill-creator 的独立前向测试方式使用子智能体：一个执行者只接收输入并生成改稿，主执行者再按清单核对。不要建立新用户会话，也不要让执行者修改技能或原稿。

脚本只检验列明的保护片段，不解析任意 Markdown，不是通用的文件或事实验证器。没有语义审阅的运行只能标为“机械检查通过，语义待核对”。

## 脚本自身的测试

```bash
node scripts/validate.mjs
node --test tests/check-preservation.test.mjs
```

这些命令只检查技能结构、样本配置与校验器行为，不会调用模型。自动检查通过不等于 19 个改稿任务通过，更不能代表跨模型稳定性。

## 真实稿件回归

在用户已授权的本地稿件中选 3–5 篇定稿，保留原件，只在隔离副本试改。优先覆盖广播站、人物书稿、正式说明。逐段核对事实、作者态度、逻辑与修改范围；字数下降只作为检查线索，不作质量分数。尚未跑真实稿件时如实标记，不把合成样本当作真实稿件验证。

原稿和测试输出留在本地，不自动放进技能包或上传 GitHub。升级本地技能不包含对外同步授权。
